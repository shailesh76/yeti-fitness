# AI Coaching Architecture

## AI Package (`@yeti/ai`)
A provider-agnostic intelligence engine built for edge environments (Deno/Edge Functions) and Node.js.
*   **Providers**: Abstracts OpenAI, Anthropic, and Gemini through a unified `AIProvider` interface. Switching LLM providers is simply a matter of changing the initialization adapter.
*   **Coaches**: Specific domains (`WorkoutCoach`, `NutritionCoach`, etc.) inject the appropriate system prompts and constraints.
*   **Context Builder**: Because mobile apps can generate huge amounts of telemetry, `AIContextBuilder` compresses WatermelonDB data arrays into dense JSON summaries to reduce token usage and improve inference speed.

## Security & Safety
1.  **No Client Keys**: API Keys only live in Supabase Secrets (`supabase secrets set OPENAI_API_KEY=...`).
2.  **Medical Constraint**: All prompts enforce strict guardrails preventing the AI from diagnosing medical conditions or injuries.
3.  **Cost Management**: The `ai_usage` table tracks requests per `athlete_id`. Free tiers are hard-limited to 5 requests per day, rejected at the Edge Function layer to prevent abuse.

## Mobile Flow
1.  User enters `apps/mobile/app/coach/index.tsx`.
2.  UI optimistically renders the user's message.
3.  App requests the Edge Function `/functions/ai-coach`, passing the message and a compressed local context (generated by `AIContextBuilder` reading WatermelonDB).
4.  Edge Function validates limits -> Generates AI response -> Returns.
5.  Response is stored in `ai_messages` and synced offline.
